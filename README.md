# UAV EI: data-driven control of a quadrotor (Track B, reinforcement learning)

Integration week of the *Data-driven Control* course (CentraleSupélec).
A quadrotor sits on a platform at the back of a ground vehicle. It must take off to **0.5 m**, then land
on the ground at **-0.25 m** (Figure 1). The drone has no documentation: every control law is built from
data only, trained with SAC on **identified models** (never on the protected `quadcopter_model.p`), then
flown on the simulator `UAV_model.slx`.

| task | what | Python | MATLAB |
|---|---|---|---|
| main | altitude: Figure 1 mission | notebooks 1-3 | `rl_interface/` |
| advanced 1 | rotate on itself at the top (four quarter turns) | notebooks 4-5, `full_mission.py` | `rl_interface_yaw/` |
| advanced 2 | land at a different position (x) | notebooks 6-7, `full_mission_x.py` | `rl_interface_x/` |
| advanced 3-4 | follow the vehicle, land on it | `full_mission_follow.py` | `rl_interface_x/` |

## Pipeline (the same for every axis)

```
 data (commands -> acceleration)    identified model             RL controller            "real" drone
 data/*.csv  ------------------->  NN  a[k+1] = F(a[k], u[k])  -->  SAC on the model  -->  MATLAB + UAV_model.slx
                                   (+ tanh model to compare)        one policy per axis    (replay check, then flight)
```

Each axis has its own policy; a fixed **mixer** turns the commands into the 4 motor commands:
`U = u_T + u_yaw [1 -1 1 -1] + u_x [-1 0 1 0] (+ u_y on motors 2/4)`, thrust first.

## How to run

```
pip install -r requirements.txt
cd python
# notebooks in order; the RL notebooks load the saved agents of models/ (set TRAIN = True to retrain)
python full_mission.py              # altitude + yaw        -> ../rl_interface_yaw/
python full_mission_x.py            # + x                   -> ../rl_interface_x/
python full_mission_follow.py       # follow the vehicle    (add "land" to land on it)
```

MATLAB (R2025a): run `EINT_RL_eval` in `rl_interface/`, `EINT_RL_eval_yaw` in `rl_interface_yaw/`, or
`EINT_RL_eval_x` / `EINT_RL_eval_follow` / `EINT_RL_eval_land_vehicle` in `rl_interface_x/`. Each first
checks that the MATLAB controller computes exactly what Python computes (replay of the `traj_*.mat`
reference flight), then flies the mission on the simulator. Only `g_noise` is meant to be changed
(0, then 0.1, then higher). The course's `EINT_RL_closed_loop.slx` is saved in R2025b: in an older
MATLAB, run `set_param(0, 'ErrorIfLoadNewModel', 'off')` first; the other loops are built by script.

**If you change an observation or a mission** in a `*_env.py`, change the matching `rl_controller*.m` the
same way, retrain, and export again.
